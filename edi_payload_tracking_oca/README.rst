Technical module keeping, for each record, the payload last exported to
a third party through EDI.

It provides:

- ``edi.payload.output``: one stored payload (JSON) per record, whatever
  its model;
- ``edi.payload.consumer.mixin``: a mixin giving records direct access
  to their stored payload.

It has no functional effect on its own. Modules exporting data can use
it to send only what changed since the last export.

Use Cases / Context
===================

Some partners (e.g. warehouse management systems) expect updates to
contain only what changed since the last export. To build such an
update, the sender needs to know what it already sent for each record.
Each integration used to store this on its own. This module stores it
once, for any model.

Usage
=====

This module is meant for developers. Inherit the mixin on the model
whose records are exported:

.. code:: python

   class ProductProduct(models.Model):
       _inherit = ["product.product", "edi.payload.consumer.mixin"]

Then, in the handlers of the exchange:

- ``record.edi_payload_get_output()`` returns the payload stored for the
  record, or an empty dict if nothing was exported yet;
- ``record.edi_payload_set_output(payload)`` replaces the stored
  payload;
- ``record._edi_payload_has_changes(payload)`` tells whether ``payload``
  holds anything not exported yet: true when nothing was exported, or
  when a key holds a value different from the stored one. Override it to
  refine the comparison for a model.

When two transactions export the same record for the first time
concurrently, the second one fails on the unique constraint. With
``edi_queue_oca``, ``edi_payload_tracking_queue_oca`` is installed
automatically and turns this into a retry of the job, which then finds
the payload stored by the first one.

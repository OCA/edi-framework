Glue between ``edi_payload_tracking_oca`` and ``edi_queue_oca``,
installed automatically with both.

When a job stores the payload of a record whose payload was just created
by a concurrent job, the job is retried instead of failing.

Use Cases / Context
===================

Exports usually run as queue jobs. Two jobs exporting the same record
for the first time at the same moment both try to create its stored
payload: the second one hits the unique constraint. Retrying that job is
enough: next time, it finds the stored payload and merges its own on top
of it.

Usage
=====

Nothing to configure. Run the exports storing payloads as queue jobs (as
``edi_queue_oca`` does for exchange records): a job failing on a
concurrent creation is retried as any ``RetryableJobError``.
